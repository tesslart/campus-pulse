# Отчёт о тестировании CAMPUS PULSE

Формат: **шаги → ожидаемо → фактически**. Обязательные для сдачи: **T02, T04, T06, T07, T12**.

Как проверялось:
- **SQL** — `supabase/rls_tests.sql` в Supabase SQL Editor (проверяет права прямо в БД, в конце `rollback`).
- **API** — `npm run test:rls` от имени двух учебных аккаунтов (атака «из консоли браузера»).
- **UI** — два браузера (обычное окно + инкогнито), пользователи А и Б.

Колонку «Фактически» заполните после проверки на своём проекте Supabase и GitHub Pages (✅ / ❌ + комментарий, при необходимости — скриншот).

| № | Сценарий | Шаги | Ожидаемо | Фактически |
|---|---|---|---|---|
| T01 | Гость видит события, но не может создавать | 1. Открыть сайт без входа. 2. Нажать «Создать». 3. `rls_tests.sql` / `npm run test:rls` | Каталог виден; на «Создать» — экран «Нужно войти»; INSERT от `anon` → `permission denied` (42501) | |
| **T02** | А создаёт событие, Б видит его после обновления | 1. Браузер 1: вход А → «Создать» → заполнить → «Опубликовать». 2. Браузер 2: вход Б → обновить афишу | Событие А появилось у Б (данные общие, из Supabase) | |
| T03 | Б записывается, видит активное состояние | Б открывает событие А → «Участвовать» | Кнопка блокируется («Записываем…»), затем «✓ Вы участвуете» + «Отменить участие»; счётчик +1; бейдж «Вы участвуете» в каталоге | |
| **T04** | Повторная запись Б не создаёт вторую строку | 1. Б дважды быстро жмёт кнопку / повторяет INSERT через API. 2. Supabase → Table Editor → event_members | Кнопка недоступна во время запроса; БД отвечает `23505 duplicate key`; в таблице одна строка (PK `event_id, user_id`) | |
| T05 | Б может отменить только своё участие | 1. Б → «Отменить участие». 2. Через API Б пытается удалить запись А | Своя запись удалена, событие осталось; запрос на чужую запись затрагивает 0 строк | |
| **T06** | Б не может изменить и удалить событие А — даже через API | 1. У Б на странице события А нет кнопок «Редактировать/Удалить». 2. Б открывает `#/edit/<id>` → «Нет доступа». 3. `npm run test:rls`: UPDATE/DELETE/смена `creator_id` от Б | UPDATE и DELETE затрагивают **0 строк**, смена автора → `permission denied`; событие не изменилось | |
| **T07** | Б не может прочитать личные записи А | `npm run test:rls` / `rls_tests.sql`: `select * from event_members` от Б | Возвращаются только строки Б; записи А не видны. Счётчик участников — только число | |
| T08 | Неверный пароль — ошибка без утечки токена | Ввести верный email и неверный пароль | «Неверный email или пароль.»; в интерфейсе и консоли нет токена/ответа сервера | |
| T09 | Нет интернета — сообщение об ошибке | DevTools → Network → Offline → обновить афишу / нажать «Участвовать» | Баннер «Нет подключения к интернету», состояние ошибки с кнопкой «Повторить»; приложение не зависает (тайм-аут 15 с) | |
| T10 | Пустые поля и неправильная дата не отправляются | «Создать» → нажать «Опубликовать» с пустыми полями; затем дата в прошлом; название из 3 символов | Ошибки под каждым полем, запрос не уходит; в календаре нельзя выбрать прошлое (`min`); БД дополнительно отклоняет прошлую дату (RLS) и неверную длину (CHECK) | |
| T11 | 375 px — нет горизонтального скролла | DevTools → iPhone SE / 375 px → все экраны | Карточки в 1 колонку, фильтры прокручиваются внутри своей панели, `scrollWidth = 375` | |
| **T12** | GitHub Pages открывается на втором устройстве и читает базу | Открыть ссылку Pages на телефоне (мобильный интернет) | Каталог загружается с теми же событиями, вход работает | |

## Результаты автоматических проверок (эталон)

`supabase/rls_tests.sql` на чистой схеме:

```
PASS T01: гость читает афишу (0 строк), но не создаёт события
PASS T02: событие А видно пользователю Б
PASS T03: Б записан, user_id проставлен автоматически
PASS T04: повторная запись отклонена первичным ключом (23505)
PASS T07: Б видит только свои записи; счётчик показывает только число (2)
PASS T05: Б отменил своё участие, запись А не затронута
PASS T06: Б не может изменить, удалить или присвоить событие А
PASS T10: БД отклоняет прошедшую дату и неверную длину полей
PASS: владелец удалил событие, записи удалены ON DELETE CASCADE
```

## Найденные и исправленные ошибки

| Ошибка | Причина | Исправление |
|---|---|---|
| Горизонтальный скролл на 375 px | ряд фильтров растягивал колонку grid | `grid-template-columns: minmax(0, 1fr)` у панели фильтров |
| Клик «Опубликовать» иногда не срабатывал | при потере фокуса появлялась ошибка над кнопкой и сдвигала её | ошибка пустого поля показывается только после ввода или отправки |
| Повторная запись при двойном клике | — | кнопка блокируется на время запроса + PK в БД + обработка `23505` |
